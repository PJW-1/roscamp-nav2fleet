# 회피 파트와의 약속 (사용자 기준)

넓은 구역에서 장애물과 다른 핑키를 피하는 일은 로봇의 Nav2가 맡고, 관제는 어느 구역에 들어가도 되는지만 정합니다. 아래는 관제 담당이 제안하는 경계입니다. 값은 Gazebo에서만 쟀고 실물에서는 재지 않았습니다.

## 1. 약속

| 항목 | 제안 |
|---|---|
| 맡는 범위 | 회피 담당: goal용 컨트롤러 `FollowPathGoal`의 설정, costmap 장애물 층(라이다, 비전). 관제 담당: bt_navigator, planner, FollowPath 셋(`FollowPath`, `FollowPathThrough`, `FollowPathReverse`), keepout |
| 고정한 이름 | 컨트롤러 이름 `FollowPathGoal`만 고정합니다. 안의 플러그인(RPP, MPPI, DWB)은 회피 담당이 바꿉니다 |
| 비전 장애물 입력 | 토픽 `/<robot>/vision_obstacles`(`sensor_msgs/PointCloud2`, map 또는 로봇 좌표)를 costmap 장애물 층의 관측원으로 넣습니다. 자리만 만들어 두었고 기본은 꺼져 있습니다(3절) |
| 회피 범위 | 관제가 잡아 준 구역 안에서만 피합니다. keepout 구역(급행, 도크, 갈림목)에는 들어가지 않습니다 |
| 못 지나갈 때 | `blocked_after_s`(5초) 동안 0.05 m도 못 나아가면 `state=BLOCKED`를 보고합니다. goal은 그대로 두고 Nav2가 계속 해 봅니다. 그다음은 관제가 정합니다 |
| 관제가 하는 것 | BLOCKED가 `blocked_mark_s`(10초) 이어지면 goal을 거두고 다른 지점을 거쳐 보냅니다. 길이 없으면 `blocked_retry_s`(60초)까지 기다립니다 |
| 다른 핑키 | costmap에 보이는 다른 핑키도 장애물로 피합니다. 관제는 넓은 구역의 정원과 우선순위(`HALL_YIELD`)로 붐비지 않게만 합니다. 두 대가 0.30 m 안에서 5초 동안 못 나아가면 우선순위가 낮은 쪽을 세우고, 같은 자리에서 또 그러면 빈 주차 자리로 보냅니다(`관제_구역교통.md`의 회복 순서) |
| 관제가 시키는 물러나기 | 넓은 구역에서 비킬 로봇이 BLOCKED를 보고했을 때만, 서기 전에 뒤로 0.12 m 물러나게 합니다(`retreat`에 경로를 넣어 `FollowPathReverse`로 보냅니다). 로봇의 회피가 먼저이고, 회피가 안 되어 BLOCKED가 온 뒤에 관제가 보냅니다. 기본은 꺼져 있습니다(`yard_backoff`). 2.3절에 조건과 한계가 있습니다 |
| 잠깐 지나가는 사람 | 8초쯤 막혔다 풀리면 관제는 아무것도 하지 않습니다(10초 전이므로). 우회도 후진도 없습니다 |
| 시험 | 상황 시험의 "넓은 마당 장애물(120초)"과 "사람이 잠깐 지나감(8초)" |

## 2.1 Gazebo에서 본 것 (핑키 세 대와 관제, 주문 8건, 2026-11-12)

경기 표는 `docs/worklog_nav2base_2026-11-12.md` 4.4절에 있습니다. 거리와 위치는 Gazebo의 실제 위치로 쟀습니다.

| 확인 | 어디서 몇 번 | 결과 |
|---|---|---|
| 마당에서 로봇의 몸이 서로 닿았나 | Gazebo, 몸 사이 틈을 잰 열 판(D2 여섯, C 둘, D 둘) | 다섯 판에서 닿았습니다(D2 넷, D 하나. 중심 사이 0.09~0.10 m). 몸은 충돌 메시의 경계 상자로 보았습니다 |
| 한 핑키의 라이다가 다른 핑키의 무엇을 보나 | Gazebo 모델(`pinky_description`)의 치수 | 빔 높이는 바닥에서 0.125 m이고 몸의 꼭대기는 0.113 m입니다. 빔은 몸 위로 지나가고 라이다 머리(지름 약 5.6 cm)에만 걸립니다. costmap에는 다른 핑키가 작은 점으로 찍힙니다 |
| Nav2 goal이 지점에서 얼마나 떨어져 끝나나 | Gazebo D 한 판, Nav2 goal 14번 | 실제 위치로 중앙값 0.057 m, 최대 0.095 m입니다. 보고 위치로는 중앙값 0.050 m, 최대 0.081 m입니다 |
| 장애물이 없을 때 Nav2 goal로 달리는 몸이 keepout 구역에 걸쳤나 | Gazebo D2 한 판(g2d), 발자국 0.12 m 사각형 | 15번 걸쳤습니다. 가장 깊게 0.05 m, 가장 길게 2.38 s, 모두 더해 13.0 s입니다 |
| 마당에 상자가 있을 때 Nav2 goal로 달리는 몸이 keepout 구역에 걸쳤나 | Gazebo D2 한 판(g3yard), 마당 가운데 0.12 m 상자를 60~180 s에 둠 | 8번 걸쳤고 그 가운데 7번이 상자가 있던 동안입니다. 가장 깊게 0.04 m, 가장 길게 2.69 s, 모두 더해 5.27 s입니다. 장애물 없는 판(g2d 15번 13.0 s, g2e 8번 7.24 s)보다 늘지 않았습니다 |
| 급행 위의 상자 앞에서 로봇이 섰나 | Gazebo D2 한 판(g3exp2), 급행 가운데 0.08 m 상자, 고정 경로의 충돌 검사는 끔 | 서지 않았습니다. 상자에 앞을 댄 채 바퀴가 헛돌았고 BLOCKED도 나오지 않았습니다. 충돌 검사를 켠 한 대 경기에서는 같은 상자 0.10 m 앞에서 서고 BLOCKED를 냈습니다 |

## 2.2 Nav2 복구 동작 (Gazebo, 2026-11-12)

Nav2 기본 행동 트리(BT)는 goal이 막히면 Spin, Wait, BackUp을 차례로 해 봅니다. 탐침 표는 `sim/fleet_gz_sim/results/backup_spin_probe.md`에 있습니다.

| 확인 | 어디서 몇 번 | 결과 |
|---|---|---|
| 세 대 경기에서 복구가 실패한 횟수 | Gazebo, 세 대 경기 로그 19개(경기마다 한 판) | Spin 실패 101번, BackUp 실패 50번입니다. 모두 "Collision Ahead"로 끝났습니다. 성공한 횟수는 모릅니다: 경기 로그는 경고부터만 남겨서 성공은 적히지 않습니다 |
| 정면에 진열대나 서 있는 핑키가 있을 때 Spin | Gazebo, 핑키 한 대, 몸 틈 0.10~0.015 m에서 10번 | 10번 모두 실패했습니다(오류 703). 0.07~0.22 rad 돌다가 멈춥니다. 빈 곳(둘레 0.32 m)에서는 2번 모두 성공했습니다. 실패가 시작되는 틈은 0.10 m와 0.32 m 사이이고 더 좁히지 않았습니다 |
| 정면에 장애물이 있고 뒤가 비었을 때 BackUp | 같은 탐침, 26번 | 25번 성공했습니다(몸 틈 0.015 m까지). 실패 한 번은 진열대 앞 0.03 m에서 났습니다(오류 714) |
| 뒤에 벽이 있을 때 BackUp | 같은 탐침, 1번(뒤 0.325 m에 벽, 0.30 m 물러나기) | 실패했습니다(오류 714). 움직이기 전에 물러날 길을 미리 검사합니다 |
| Nav2가 쓰는 발자국 | 같은 탐침, `local_costmap/published_footprint` | 0.14 m 정사각형입니다. 설정은 0.12 m인데 `footprint_padding` 기본값 0.01 m가 붙습니다. 옆으로 몸보다 0.023~0.029 m 넓습니다 |
| 옆이나 뒤 모서리에 장애물이 있을 때 | 재지 않았습니다 | 경기의 BackUp 실패 50번은 정면 탐침으로 설명되지 않습니다. 경기에서는 옆이나 뒤 모서리 0.01~0.07 m에 다른 핑키나 벽이 있었습니다. 다음에 잴 것입니다 |

## 2.3 관제가 시키는 물러나기 (제안, 기본 꺼짐)

| 항목 | 내용 |
|---|---|
| 언제 | 넓은 구역에서 두 대가 가까이 서서 못 나아가고(규칙 6), 비킬 로봇이 BLOCKED를 보고했을 때입니다. BLOCKED 보고가 없으면 `yard_backoff_wait_s`(0.5초)를 더 기다렸다가 그냥 세웁니다 |
| 무엇을 | `retreat`에 곧은 경로(지금 자리에서 뒤로 `yard_backoff_m` 0.12 m)를 넣어 보냅니다. 핑키는 `FollowPathReverse`로 0.05 m/s로 따릅니다. 끝나면 5초 서 있다가 원래 목적지를 다시 받습니다 |
| 내지 않는 때 | 뒤로 가는 선이 로봇이 쥔 넓은 구역을 벗어나거나, 진열대를 지나거나, 끝 자리가 벽·진열대·고정 구간에서 0.10 m 안이거나, 뒤쪽 0.20 m 안에 다른 로봇이 있거나, 끝 자리가 그 로봇이 쥐지 않은 지점에서 0.20 m(`node_clear_m`) 안일 때입니다(다른 로봇이 그 지점을 쥐었거나 나중에 잡을 수 있습니다). 그때는 그 자리에 세웁니다 |
| 실패하면 | 시도 횟수로 세지 않고 그 자리에 세웁니다(`HALL_BACKOFF_FAILED`) |
| 한계 | `FollowPathReverse`의 충돌 검사가 켜져 있으면 바로 옆의 로봇 때문에 `OBSTACLE_BEHIND`로 끝날 수 있습니다. Gazebo 경기는 고정 경로의 충돌 검사를 끄고 돌렸습니다. Gazebo 세 대 경기로는 아직 재지 않았습니다(머리 없는 세계에서만 시험했습니다) |
| 건드리지 않은 것 | Nav2 설정, 행동 트리, `FollowPathGoal`, costmap 장애물 층은 바꾸지 않았습니다 |

## 3. 코드에 만들어 둔 자리

| 자리 | 어디 | 기본 |
|---|---|---|
| 비전 장애물 관측원 | `pinky_nav_config`의 `nav2.launch.py` 인자 `vision_obstacles:=true` | 꺼짐. 켜면 local과 global costmap 장애물 층에 `/<robot>/vision_obstacles`를 관측원으로 더합니다 |
| goal용 컨트롤러 | `nav2_params.yaml`의 `FollowPathGoal` | RPP, 충돌 검사 켬 |
| keepout 마스크 | `tools/make_keepout.py`가 구역 지도와 맵 yaml에서 만듭니다. `nav2.launch.py`의 `keepout_mask:=<yaml>` | 비면 필터를 띄우지 않습니다 |

## 4. 회피 담당에게 묻는 것

| 물음 | 까닭 |
|---|---|
| 급행(폭 0.20 m)과 갈림목에서 충돌 검사를 어떻게 둘까요 | 몸 반폭 0.06 m에 여유가 0.04 m뿐이어서, 라이다 잡음이 벽을 몸 발자국 안에 찍으면 FollowPath가 섭니다. Gazebo 결과와 조정값은 작업 기록에 있습니다. 검사를 끈 채로는 급행 위 상자 앞에서 로봇이 서지 않았습니다(2.1절) |
| 비전 장애물의 좌표계와 주기 | 관측원 설정(`expected_update_rate`, `obstacle_max_range`)을 맞추기 위해서입니다 |
| keepout을 얼마나 넓힐까요(지금 0.06 m) | 0.06 m는 곧게 선 몸의 반폭입니다. 45도로 선 몸의 모서리는 0.085 m까지 나가서 구역에 0.025 m 걸칠 수 있습니다. `tools/make_keepout.py --pad 0.085`로 바꿀 수 있고, 그만큼 마당이 좁아집니다 |
| 비전 장애물 표시를 언제 지울까요 | 지금 자리는 표시만 합니다. 찍힌 칸은 라이다 광선이 지나갈 때만 지워지고, 시간으로는 지워지지 않습니다 |
| 다른 핑키의 몸을 costmap에 어떻게 넣을까요 | Gazebo에서 라이다는 다른 핑키의 라이다 머리만 봅니다(2.1절). 세 대 경기 열 판 가운데 다섯 판에서 몸이 닿았습니다. 실물 핑키도 몸이 라이다 빔보다 낮으면 같습니다. 관제가 다른 로봇의 위치를 장애물로 내주는 방법도 있습니다 |
| BLOCKED 기준 5초, 0.05 m가 맞나요 | `FollowPathGoal`을 바꾸면 제자리에서 도는 시간이 달라질 수 있습니다 |
| local costmap의 `footprint_padding`을 0으로 둘까요 | 지금은 기본값 0.01 m가 붙어 발자국이 0.14 m입니다(2.2절). 급행 폭 0.20 m에서 여유가 0.03 m로 줄고, Spin과 BackUp의 미리 검사에도 이 발자국이 쓰입니다 |

## 5. 회피 구현 안건 (추가 지시서 2의 7절)

회피 담당과 상의할 안건입니다. 코드는 바꾸지 않았습니다.

| 안건 | 제안 | 근거 |
|---|---|---|
| NavigateToPose 행동 트리의 Spin | 빼거나, 넓은 곳에서만 하게 합니다 | 정면 0.10 m 안에 무언가 있으면 10번 모두 실패했고, 세 대 경기에서 101번 실패했습니다(2.2절) |
| BackUp | 그 자리에서 곧게 물러나는 대신, 지나온 길을 따라 자기가 쥔 구역(base) 안에서 후진하게 합니다 | 세 대 경기에서 50번 실패했습니다. 관제의 `retreat`(경로 후진)가 같은 방식입니다 |
| 마주 선 두 대(대칭 깨기) | 우선순위가 낮은 쪽이 먼저 물러나거나, 로봇마다 다른 시간만큼 기다린 뒤 다시 계획합니다 | 두 대가 같은 규칙으로 피하면 같은 쪽으로 비켜서 다시 마주 섭니다 |
| 순서 | 기다림 → 우선순위가 낮은 쪽이 물러남 → BLOCKED 보고 | 관제의 회복 순서(섬 → 물러남 → 주차 자리)와 같은 차례입니다 |

계약에 미치는 것:

| 항목 | 지금 | 바뀌면 |
|---|---|---|
| BLOCKED를 보고하는 때 | 5초 동안 0.05 m를 못 나아가면 보고합니다 | 로봇이 스스로 기다리고 물러난 뒤에 보고하면 더 늦어집니다. 관제의 `near_stuck_s`(5초), `yard_backoff_wait_s`(0.5초), `stall_s`(6초)와 시험의 반응 한도(BLOCKED 뒤 1초 안에 관제가 반응)를 다시 맞춰야 합니다 |
| MoveTo의 우선순위 | 칸이 없습니다 | 로봇이 우선순위로 대칭을 깨려면 관제가 goal에 `priority`를 넣어 줘야 합니다(새 칸, 제안) |
| 비전 장애물의 종류 | PointCloud2 한 가지입니다 | 사람, 상자, 다른 핑키를 구별해 주면 기다릴지 돌아갈지를 달리할 수 있습니다 |

회피를 바꾼 뒤 다시 맞출 관제 값: 규칙 6의 거리와 시간(`near_m`, `near_stuck_s`), `blocked_after_s`, order 모델의 `lookahead_s`.
