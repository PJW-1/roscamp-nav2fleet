## 4. 측정

### 4.1 Gazebo: 핑키 한 대, D2 (2단계)

- 어디서: Gazebo(WSL2, 화면 없음, ROS 도메인 60), 배치 D2, `one_pinky.launch.py`(Nav2, pinky_fsm, keepout 켬, 최고 속도 0.12 m/s), 관제 없음. 브랜치 `sites`의 a44abbf를 빌드했습니다.
- 위치와 방향 오차는 Gazebo의 실제 위치를 목표 지점과 비교한 값입니다.

### 4.2 Gazebo: 충돌 검사를 켠 채 고정 경로 (지시서 3절)

**목표(모든 실행에서 충돌 검사 켬)를 이루지 못했습니다.** 여덟 번 띄워 설정을 바꿔 보았지만, D2의 고정 경로를 모두 통과한 설정은 없었습니다. 마당의 Nav2 goal은 켠 채로 모두 성공했습니다.

| update가 거절됐을 때 | 이전 base 끝까지 가고 거기서 새 order. 실패 횟수로 세지 않습니다 | 이전 goal은 살아 있습니다 |

| 목적이 바뀐 order | base를 줄이지 않습니다. 로봇이 넓은 구역에 나오면 취소하고 새 order | 갈림목이나 급행 안에서 서지 않게 합니다 |
| base 밖 조각을 끝냈다는 보고 | 믿지 않고 `SEGMENT_BEYOND_BASE`를 남깁니다 | 보고가 틀려도 관제가 구역 밖에 로봇이 있다고 믿지 않게 합니다 |
| 이은 자리의 허용 오차 | 핑키는 조각 끝에서 2 cm, Nav2 goal 조각은 0.15 m 안이면 다음 조각으로 넘어갑니다 | Gazebo에서 Nav2 goal이 0.05~0.10 m 앞에 섰습니다 |
| horizon 경고 | feedback에 `horizon_warning` 칸을 더했습니다 | 추가 지시서 표에 없던 칸입니다. 경고를 관제에 전할 길이 필요했습니다 |
| base 끝에서 미리 속도 줄이기 | 만들지 않았습니다 | 추가 지시서의 선택 사항입니다 |

|---|---|
| order 모델의 이득은 이 표에 보이지 않습니다 | 머리 없는 세계는 0.1 s 걸음으로 돌고, ROS 액션 왕복과 Nav2 계획 시간을 흉내 내지 않습니다. 그래서 끈 상태의 이음매 공백도 한 걸음(0.10 s)입니다. 구간 사이에 서는 시간이 얼마나 줄어드는지는 Gazebo 측정으로 봐야 합니다 |

### 8.4 남은 위험

| 무엇 | 지금 |
|---|---|
| 통신이 끊긴 로봇이 base 끝까지 감 | base의 구역은 "예상 도착 + 3 s"까지 잡혀 있습니다. 그 사이 로봇 앞이 막히면 로봇이 스스로 섭니다. 예상보다 늦게 닿으면 구역이 먼저 풀릴 수 있습니다 |
| 이은 자리의 위치 오차 | Nav2 goal 조각 뒤에 `follow_path` 조각이 오면 0.05~0.10 m 어긋난 채 시작합니다 |
| 두 goal을 취소한 뒤의 새 order | 취소 확인보다 먼저 갈 수 있습니다. 로봇이 update 번호 0을 새 order로 받는 것에 기대고 있습니다 |
| 속도를 미리 줄이지 않음 | 로봇은 base 끝에서 지금 방식대로 섭니다. 미리 늘리기가 늦으면 섰다가 다시 갑니다 |
| ROS 가짜 핑키 | order goal을 받지 않습니다. order 모델을 켠 ROS 시나리오 시험은 없고, 켠 상태의 검증은 머리 없는 세계와 Gazebo(진짜 `pinky_fsm`)로 했습니다 |
| 머리 없는 세계의 한계 | 액션 왕복 시간이 없어서 order 모델의 이득과 늦은 update의 영향을 재지 못합니다 |
