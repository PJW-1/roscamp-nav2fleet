## 4. 사용자가 정할 것

1. **RL 기본을 RL 혼자로 할지 RL+shim으로 할지.** shim 쪽이 d_robot(6/6 대 1/6)과 몸 거리(세 시나리오에서 0.02~0.04 m 더 넓음)에서 낫다. 비용은 Q2 → E-3 벽 접촉 한 번이다. shim은 지금 시뮬 덮어쓰기(`sim/fleet_gz_sim/nav_overrides/follow_path_rl_shim.yaml`)에만 있고, `angular_dist_threshold` 0.785는 제안 값이다. 기본으로 정하면 실물 `nav2_params.yaml`에도 넣는다.
2. **뒤 가드(`rear_stop_range`)를 켤지.** 오늘 비교는 가드를 끄고(0.0) 돌렸다. 가드는 플러그인에서 후진 명령을 잘라 내는 빠른 확인일 뿐이다. 정책은 후진을 쓰도록 학습되었으므로, 가드를 켜면 닫힌 고리가 학습 때와 달라진다. 또 가드는 뒤쪽 ±30°의 광선만 본다. 예전 정책의 528개 출발 점검에서 뒤 왼쪽 모서리가 옆으로 닿은 E-3 출발 넷은 가드로 막지 못했다(`docs/worklog_follow_path_rl_2026-11-21.md` 11.3절). 그러므로 가드를 벽 스침 방지 수단으로 믿으면 안 된다.
3. **노드 예약의 꼭짓점 시각 틈(B62).** 지나가는 노드의 꼭짓점에 정확히 선 한 스텝 동안 다음 노드를 놓는다. 고쳐 보았더니(`f0114fe`) 기다리는 두 로봇이 서로 막아 교착해 되돌렸다(`5b55b75`). 그대로 둘지 정해 주면 된다.
4. **가짜 로봇(`sim/fake_robots`) 속도 0.18~0.20.** 출처(0.12) 밖이다. 관제 시험의 시각이 움직이므로 지금은 그대로 두었다.
5. **의도 비교의 나머지 8판.** 오늘은 GPU 시간이 4c 한 판(의도 없음, seed 1)만 되었다. 의도 / 의도+우선권 변형과 남은 seed는 다음 밤에 돌린다. 반복 수를 오늘 판과 같은 600번으로 맞출지, 더 길게 할지 정해야 한다. 600번이면 한 판에 약 67분이므로, 8판은 한 밤(22:00~07:00)에 다 들어가지 않는다.

| MPPI `time_steps` | 83(시뮬 상한이 더 낮으면 같은 비율로 늘림) | 0.50 m 앞을 유지 |
| 4b 반복 수 | 1000번 | 에피소드가 2.08배 길다 |
| 대본 로봇 속도 배율 | 0.67~1.0 | 실제 Pode는 출처 속도를 넘지 않는다 |
| 비교 판 수 | 칸마다 6판(Williams 순서) | 완전 균형인 8판은 시간 안에 들지 않았다 |
| 스침을 충돌로 | Gazebo bench와 Isaac이 같은 정의 | 학습 정의와 평가 정의를 맞춘다 |

## 6. 알아야 할 포인트

- **로봇에 새로 배포해야 한다.** `make_params.py`는 import 때 `nav_speed.yaml`을 찾는다. 이 파일이 없는 옛 배포에서는 `start.sh`가 바로 실패한다. 이번에는 로봇에 손대지 않았다(`deploy.sh` 안 돌림).
- **실물 Nav2에는 이제 MPPI가 없다.** controller_selector로 MPPI를 고르면 실패한다.
- **0.12는 실물과 시뮬의 기본이다.** 예전 Gazebo 기본 0.20으로 잰 결과와 시간·속도 지표를 바로 견주면 안 된다.
- **옛 0.25 체크포인트를 지금 다시 내보내면 명세가 틀린다.** `export_policy.py`는 v_max를 지금의 `task_spec`에서 쓰므로 0.12가 적힌다.
- **성공은 실제 위치로 본다.** 부딪혀 AMCL이 틀어지면 Nav2는 엉뚱한 곳에서 도착했다고 한다.
- **RotationShim은 "먼저 돌고, 그다음 맡긴다".** 방향 차이가 45°보다 크면 제자리에서 돌고, 그 안으로 들어오면 RL에 넘긴다. 그래서 RL은 큰 방향 오차를 거의 보지 않는다.
- **Isaac 점검과 Gazebo의 차이.** 528개 출발 점검은 정해진 자리와 30° 간격 방향만 본다. shim이 넘겨준 직후 같은 상태는 그 안에 없을 수 있다.
